Removed those three debug checks, preserving foreground gating, private-subnet restriction, bootstrap destination allowlist, TLS hostname verification and shared signed identity admission. The legacy unsigned room-based LAN diagnostic stays debug-only.

Emulator-5554 remained connected with Wi-Fi disabled and reconnected after background/foreground in that condition; Wi-Fi restored afterward. This is emulator transport evidence, not a physical carrier test or closed-app notification proof.

## Release call regression work (October 3 evening)

Real non-debuggable release testing on emulator-5554 (Emul/18) and emulator-5556 (Emulator/14) reproduced permission/lifecycle races. Outgoing calls now await identity and peer-route reattachment after permission dialogs. Incoming ringing calls have a bounded, owner-scoped in-memory permission hold so normal recovery does not reject them during an Android prompt; cancelled and established calls are not resurrected. Initial media setup permits up to ten seconds for route recovery. Changed established media contexts still fail closed.

Android previously closed every axon on background even during a protected call. The native transport now preserves existing axons only for a connected call with the app's actual foreground call service running. Ordinary backgrounding, logout, call termination and module destruction retain teardown. New outbound native connections still require foreground. Emulator retest verified voice calls with both apps backgrounded and returned, mute/speaker controls, video with first camera prompts on both sides, rendered remote video, camera off and video background/return, and hangup cleanup. Native call service was absent after hangup. No physical audio-quality or carrier-network result is implied.

The background incoming-call test uncovered rejected legacy push migration bindings for the emulator identities. Added sanitized registration-state diagnostics (no tokens/payloads), bounded retry without a rejected optional migration ticket, and rotation of this installation's FCM token if it is still leased to a previous identity. Existing legacy bindings are not reassigned. Live notification retest is pending; do not label the candidate fully verified until that result is recorded.

Current validation: TypeScript passes; 732 unit tests pass; service dependency check passes (181 modules); native release tests pass. Local Gradle builds and reinstall-in-place were used, preserving accounts/data. No new phone APK has been created during this regression run yet. Evidence is under Axonic-app/builds (release-regression-unit.log, emulator-call-regression-build.log, voice-both-background.png, camera-route-fixed.png, video-background-fixed.png).

Final emulator notification result: both identities registered successfully after the rejected migration-ticket fallback. Bounded waiting for persistent-axon request capacity prevents registration retries from starving behind periodic relay/directory work. Android displayed an incoming-call notification while emulator-5556 was backgrounded. Opening it restored the invitation; answering connected voice media (screenshot background-notification-call.png). A transient call-bound route gap initially caused termination; the coordinator now retains the same call-bound media transport for up to ten seconds while routes recover, rejects signaling during the gap, and still terminates a changed direct session. Regression tests cover this behavior.

Final checks: 734 mobile unit tests, TypeScript, service dependency check, native release tests, and 76 hosted tests pass. Shared persistentAxon source was synchronized and the hosted code compiled locally; no deployment was required for the mobile fixes. A normal text sent between the emulators was displayed on the recipient after call testing. This does not certify all features or physical-device microphone/speaker quality, separate carrier networks, force-stop behavior, or cold-process notification recovery. The ARM64 phone APK is being compiled locally with the existing release key and all three production feature flags.
